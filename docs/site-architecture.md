# KYDW_TRY 站点信息架构与页面职责

## 1. 站点定位

网站首先回答三个问题：KYDW 是什么、这里有哪些项目与活动、读者可以从哪里继续阅读或实践。首页承担团队入口，不直接把某一个项目或专业方向当作网站身份。

公开内容分为三条主线：

1. 团队介绍：团队定位、发展方式、成果产出、成员去向与负责人。
2. 项目与活动：按时间/阶段展示培训、合作项目、科研体验和专题活动。
3. 资源中心：按资料类型整理专业解读、项目与活动资料、教学文档；公告内容有实际材料后再单独加入。

## 2. 顶部导航

顶部导航固定为：

| 导航 | 页面职责 | 不承担的内容 |
| --- | --- | --- |
| 主页 | 说明 KYDW，并展示团队重点、近期项目和资源入口 | 不代替团队介绍页，不直接展开全部专业问答 |
| 团队介绍 | 完整介绍团队、成果、成员发展和组织成员 | 不把单个项目作为团队身份 |
| 项目与活动 | 按时间/阶段排列每个活动或项目，并进入各自详情页 | 不承载专业解读和资料库的全部内容 |
| 资源中心 | 以合集和文档库组织公告、专业解读、项目资料、教学资料 | 不把项目工作流写成泛泛的学习口号 |

科研入门体验项目属于“项目与活动”中的重点项目；专业解读属于“资源中心 / 专业解读”合集。

## 3. 首页顺序

### 3.1 首屏：先建立团队身份

首屏使用“科研大王 KYDW”作为主标题，副标题直接说明团队是学生自主运营的跨校、跨学科科研协作团队，内容涵盖科研入门、项目实践、专业解读和经验分享。首屏按钮只进入三类主内容：团队介绍、项目与活动、资源中心。

这样新访客无需预先知道某个项目名称，就能理解网站用途；科研体验的入口放在项目展示区域，不抢占团队身份的首屏位置。

### 3.2 团队概览

首页展示团队简介、代表性产出摘要、成员高校和负责人入口。团队简介与负责人放在左列，成果与成员高校放在右列；右列卡片按内容自然收缩并从顶部排列，不用空白区域强行撑成等高。负责人列表在卡片内部滚动，完整成果、成员去向和负责人详情通过团队介绍页及其子页面承载。

“成员高校”是团队概览中的一个统一板块，分为“已毕业成员高校”和“在校本科生成员高校”两组；已毕业成员高校再按“直博”和“研究型硕士”上下分列。首页与团队介绍页的学校标签显示为“学校*人数”，按对应学位组汇总；“成员升学去向”子页面继续显示具体学位和人数。两组信息都来自 `content.js` 的成员数据，不使用悬浮人数提示。

### 3.3 项目与活动重点展示

使用左右结构：

- 左侧为当前重点项目“本科生科研入门体验项目”，使用较大卡片和 new 标记，说明它是什么、包含哪些内容、进入后会看到什么。
- 右侧为可局部滚动的活动列，展示山东大学本科生暑期名校课程-神经影像学与人工智能、KYDW科研入门培训、复旦大学秋季学期本科生践悟课程和生物医学人工智能专题交流等内容。

体验项目、山东大学课程、科研入门培训和复旦课程在卡片内部提供快捷入口；快捷入口统一放在“查看详情”上方，不另设悬浮在活动区域外的按钮。体验项目显示 Week 1—5，当前仅 Week 1 可进入，其余使用灰色锁定蒙版；复旦课程按授课标题列出，尚未开放的授课同样锁定。详情按钮统一使用“查看详情”，不追加箭头。

### 3.4 资源中心预览

首页展示资源中心的合集卡片：专业解读、项目与活动资料、教学文档。卡片说明合集用途，不把“生医工”提升为顶层栏目，也不在活动区域旁边追加专业解读按钮；升学与就业内容归入专业解读页面的专题区域。

## 4. 项目与活动层级

项目与活动总览将本科生科研入门体验项目置于首位，其后按项目的历史/开展阶段排列。每个活动都有独立详情页，页面结构统一为：活动定位、正文说明、授课或课程入口和必要的进入入口。

KYDW科研入门培训单独使用章节目录，培训总览下设序言、基础知识、初识人工智能、挑战赛、基础科研、进阶科研、探索学科前沿、知行合一 自强不息、科研工具与技能以及两个附录页面；培训路径另设独立页面，集中说明基础学习、项目考核、实践进阶和合作渠道。

本科生科研入门体验项目使用以下层级：

```text
项目与活动
└── 本科生科研入门体验项目
    ├── 周页面
    │   └── 三个方向的项目卡片
    │       ├── 项目简介（只有一层内容时）
    │       ├── 体验项目简介
    │       └── 进阶项目简介（有进阶材料时显示）
    └── 项目详情页
        ├── 单层项目：教学项目、实践项目、参考答案
        └── 双层项目：体验版与进阶版各自包含教学项目、实践项目、参考答案
```

只有体验材料的方向直接称为“项目”；同时拥有体验和进阶材料的方向，在周页面左右并列显示“体验项目”和“进阶项目”。项目详情页必须有返回所属周页面和返回项目总览的按钮。

## 5. 资料在两个场景中的呈现

同一份教学 HTML 可以被两个入口引用，但语境不同：

- 项目页面：它是某个研究方向的学习材料，和项目说明、实践入口、参考答案放在同一条项目路径中。
- 资源中心：它是文档库中的一本教学文档，以书籍/资料卡形式按主题、方向和材料类型陈列。

资源中心不复制项目说明，而是复用资料链接和摘要；新增教学 HTML 时只需在内容模型中登记一次资料条目，再由项目页和文档库共同渲染。

本科生科研入门体验项目的 00—05 原材料与网站 01—06 项目的对应关系、体验/进阶路径和替换规则，统一记录在 [`experience-materials.md`](experience-materials.md)。导入新教学页、Notebook 或解析页时，先更新该维护表，再检查 `content.js` 中的项目字段。

## 6. 扩展方式

- 新增活动：在 `modules` 中登记顺序、时间/阶段标签、详情页和首页展示状态，并创建对应活动页。
- 新增授课或课程入口：在对应 `modules` 项目的 `quickLinks` 中登记标题、站内地址和开放状态；锁定项目不填写可访问地址，由统一灰色蒙版显示。
- 新增周次：在 `experience.weeks` 中增加一条周数据，周页面自动按其中的项目列表渲染。
- 新增项目：在 `projects` 中登记项目简介、输入、输出、资料入口、实践入口和参考答案；没有进阶材料时不显示“进阶项目”空卡。
- 新增专业/行业/细分方向：在资源中心的“专业解读”合集下添加专题，不新增顶部导航。
- 新增文档：登记文档库条目，并在所属项目的资料区复用同一入口。
- 更新成员去向：只修改 `team.destinationRecords`；首页和团队页的“成员高校”自动读取去向高校名称，成员去向子页自动读取地区、学位和人数，同时维护 `team.undergraduateNetwork` 以更新在校本科生高校组。

## 7. 内容联动与维护约定

主页不是独立的第二套内容。它是 `content.js` 中团队、项目和资源数据的摘要视图；修改某个数据对象后，必须检查下表列出的所有页面。

| 单一数据源 | 使用位置 | 修改时必须同步检查 |
| --- | --- | --- |
| `team.lead` | 首页首屏、团队介绍首屏 | 团队定位改变时同时检查首页首屏、团队介绍和页脚定位语句 |
| `team.paragraphs` | 首页团队概况前两段、团队介绍全文 | 首页只取前两段；新增、调序或重写段落时检查两处的阅读连续性 |
| `team.facts` | 团队介绍概况统计、首页“团队概况”说明中的成员数 | 成员数改变时只改 `facts`，确认首页摘要不再出现旧数字 |
| `team.leaders` | 首页负责人滚动卡片、团队介绍页负责人部分、负责人子页面 | 只在数据层改姓名、顺序、职务、简介和详细段落；不要在 `site.js` 另写一份负责人文案 |
| `team.destinationRecords` | 首页与团队介绍页的直博/研究型硕士高校标签、成员升学去向子页面 | 新增或修正去向时改记录；概览标签会按学位组汇总为“学校*人数”，详情页会按学校和学位显示“学位 × 人数” |
| `team.destinationUniversityOrder` | 首页、团队介绍页和成员去向页的高校顺序 | 新增高校后同时加入排序数组，避免同一学校在不同页面位置漂移 |
| `team.undergraduateNetwork` | 首页、团队介绍页、成员去向页的在校本科生高校 | 新增或删除在校高校时只改此数组，并检查三处标题和范围是否仍准确 |
| `team.achievementMetrics` 与 `team.achievements` | 首页成果数字卡、团队介绍成果区、完整成果子页面 | 成果数量或分类改变时同时核对摘要数字和详细条目；两者当前是“摘要 + 详情”两层数据，不可只改其中一层 |
| `modules`、`experience`、`projects` | 首页项目与活动、项目与活动目录、各项目/周页面、实践入口 | 项目名称、开放状态、快捷入口或项目层级改变时检查首页卡片、目录、周页、项目详情和资源中心资料入口；体验项目材料还要按 [`experience-materials.md`](experience-materials.md) 核对编号和三类文件 |
| `resourceCollections` | 首页资源中心预览、资源中心目录、专业解读和教学文档库 | 新增合集或文档时保持“合集 → 子页面/文档”的层级，不把单个专题提升为顶部导航 |

页面代码只负责渲染关系：`home()` 负责首页组合，`memberNetwork()` 负责成员高校概览，`destinationDegreeCards()` 负责成员去向详情，`leaderPreview()` 负责负责人折叠简介。今后优先修改 `content.js`，只有布局或页面层级确实变化时才修改 `site.js`；不要把数据直接硬编码到页面模板。

### 修改后的最小同步流程

1. 先在 `content.js` 修改单一数据源，并搜索对应字段在 `site.js` 中的渲染位置。
2. 检查受影响的首页、上级合集页和详情页；特别是负责人、成员去向、成果数字和项目开放状态。
3. 运行 `node --check content.js`、`node --check site.js` 与 `git diff --check`，再用静态服务器检查实际页面路径和站内链接。
4. 桌面端和窄屏各看一次：负责人卡片应在块内滚动，右侧成果与成员高校卡片应按内容收缩，不添加填充空白。

### 页面内容边界

- 公开页面使用面向读者的正式表述，不出现制作过程、内部编排、人工智能对话或占位说明。
- 维护文档记录数据依赖和实现规则，不把维护提示复制到公开页面。
- 顶部导航只保留“主页、团队介绍、项目与活动、资源中心”；专业、行业和细分方向继续归入资源中心对应合集。
- 项目详情只按实际材料显示教学项目、实践项目和参考答案；没有材料时不生成空卡片或泛化说明。

## 8. 文案与按钮规则

- 标题使用名词或明确动作，例如“科研大王 KYDW”“团队介绍”“项目与活动”“教学文档库”。
- 说明先回答“是什么”，再说明“包含什么”，最后给出“查看详情”或“进入项目”等动作。
- 不使用没有上下文的口号、对话式元话语和内部制作词汇。
- 不把专业解读放在非专业访客无法理解的快捷入口位置。
- 页面内部返回按钮使用“返回项目详情”“返回所属周次”“返回项目与活动”等明确层级名称。

## 9. 自审清单

每次改动后检查：

1. 第一次打开首页的访客能否在首屏知道 KYDW 是什么。
2. 顶部导航是否只有四项，并且每项职责互不重复。
3. 首页项目展示是否体现“当前重点 + 其他活动”，而非把某一项目误作团队主页。
4. 专业解读是否只在资源中心及其专题入口出现。
5. 周页面是否能同时理解体验项目和进阶项目的区别。
6. 项目详情页是否只保留教学项目、实践项目、参考答案及返回上级按钮；单层项目不显示进阶层级。
7. 教学文档是否同时出现在项目资料区与资源中心文档库。
8. 新增周次、项目、活动或专业专题时，是否只需添加数据和页面，不需要改变主页层级。
9. 桌面和移动端是否都能读清主次关系，右侧活动列是否保留局部滚动。
10. 团队成员、负责人、成果、成员去向或项目状态修改后，所有依赖页面是否已经从同一数据源重新渲染。
11. 首页团队概况右列是否按内容收缩，负责人内容是否只在负责人卡片内部滚动，没有新增空白填充。
