# KYDW_TRY 站点信息架构与页面职责

## 1. 站点定位

网站首先回答三个问题：KYDW 是什么、这里有哪些项目与活动、读者可以从哪里继续阅读或实践。首页承担团队入口，不直接把某一个项目或专业方向当作网站身份。

公开内容分为三条主线：

1. 团队介绍：团队定位、发展方式、成果产出、成员去向与负责人。
2. 项目与活动：按时间/阶段展示培训、合作项目、科研体验和专题活动。
3. 资源中心：按资料类型整理专业解读、项目与活动资料、教学文档；公告内容有实际材料后再单独加入。

## 2. 顶部导航

顶部导航固定为：

| 导航 | 页面职责 | 不承担的内容 |
| --- | --- | --- |
| 主页 | 说明 KYDW，并展示团队重点、近期项目和资源入口 | 不代替团队介绍页，不直接展开全部专业问答 |
| 团队介绍 | 完整介绍团队、成果、成员发展和组织成员 | 不把单个项目作为团队身份 |
| 项目与活动 | 按时间/阶段排列每个活动或项目，并进入各自详情页 | 不承载专业解读和资料库的全部内容 |
| 资源中心 | 以合集和文档库组织公告、专业解读、项目资料、教学资料 | 不把项目工作流写成泛泛的学习口号 |

科研入门体验项目属于“项目与活动”中的重点项目；专业解读属于“资源中心 / 专业解读”合集。

## 3. 首页顺序

### 3.1 首屏：先建立团队身份

首屏使用“科研大王 KYDW”作为主标题，副标题直接说明团队是学生自主运营的跨校、跨学科科研协作团队，内容涵盖科研入门、项目实践、专业解读和经验分享。首屏按钮只进入三类主内容：团队介绍、项目与活动、资源中心。

这样新访客无需预先知道某个项目名称，就能理解网站用途；科研体验的入口放在项目展示区域，不抢占团队身份的首屏位置。

### 3.2 团队概览

首页展示团队简介、成立时间、协作范围和代表性产出摘要。完整成果、成员去向、活动体系和负责人信息通过团队介绍页及其子页面承载，首页只保留足以建立信任和兴趣的摘要。

“成员高校”是团队概览中的一个统一板块，分为“已毕业成员高校”和“在校本科生成员高校”两组。前者只展示学校名称，具体学位和人数进入“成员升学去向”子页面查看；后者展示当前在校本科生所在高校。两组信息都来自 `content.js` 的成员数据，不使用悬浮人数提示，避免把成员高校卡片做成统计图表。

### 3.3 项目与活动重点展示

使用左右结构：

- 左侧为当前重点项目“本科生科研入门体验项目”，使用较大卡片和 new 标记，说明它是什么、包含哪些内容、进入后会看到什么。
- 右侧为可局部滚动的活动列，展示山东大学项目、KYDW 科研入门培训、复旦项目和生物医学人工智能专题交流等内容。

“查看详情”统一进入项目与活动详情页；首页不使用脱离上下文的项目快捷按钮，也不在活动区域追加专业方向快捷按钮。

### 3.4 资源中心预览

首页展示资源中心的合集卡片：专业解读、项目与活动资料、教学文档。卡片说明合集用途，不把“生医工”提升为顶层栏目，也不在活动区域旁边追加专业解读按钮；升学与就业内容归入专业解读页面的专题区域。

## 4. 项目与活动层级

项目与活动总览按项目的历史/开展阶段排序。每个活动都有独立详情页，页面结构统一为：活动定位、正文说明和必要的进入入口。

本科生科研入门体验项目使用以下层级：

```text
项目与活动
└── 本科生科研入门体验项目
    ├── 周页面
    │   └── 三个方向的项目卡片
    │       ├── 项目简介（只有一层内容时）
    │       ├── 体验项目简介
    │       └── 进阶项目简介（有进阶材料时显示）
    └── 项目详情页
        ├── 单层项目：教学项目、实践项目、参考答案
        └── 双层项目：体验版与进阶版各自包含教学项目、实践项目、参考答案
```

只有体验材料的方向直接称为“项目”；同时拥有体验和进阶材料的方向，在周页面左右并列显示“体验项目”和“进阶项目”。项目详情页必须有返回所属周页面和返回项目总览的按钮。

## 5. 资料在两个场景中的呈现

同一份教学 HTML 可以被两个入口引用，但语境不同：

- 项目页面：它是某个研究方向的学习材料，和项目说明、实践入口、参考答案放在同一条项目路径中。
- 资源中心：它是文档库中的一本教学文档，以书籍/资料卡形式按主题、方向和材料类型陈列。

资源中心不复制项目说明，而是复用资料链接和摘要；新增教学 HTML 时只需在内容模型中登记一次资料条目，再由项目页和文档库共同渲染。

## 6. 扩展方式

- 新增活动：在 `modules` 中登记顺序、时间/阶段标签、详情页和首页展示状态，并创建对应活动页。
- 新增周次：在 `experience.weeks` 中增加一条周数据，周页面自动按其中的项目列表渲染。
- 新增项目：在 `projects` 中登记项目简介、输入、输出、资料入口、实践入口和参考答案；没有进阶材料时不显示“进阶项目”空卡。
- 新增专业/行业/细分方向：在资源中心的“专业解读”合集下添加专题，不新增顶部导航。
- 新增文档：登记文档库条目，并在所属项目的资料区复用同一入口。
- 更新成员去向：只修改 `team.destinationRecords`；首页和团队页的“成员高校”自动读取去向高校名称，成员去向子页自动读取地区、学位和人数，同时维护 `team.undergraduateNetwork` 以更新在校本科生高校组。

## 7. 文案与按钮规则

- 标题使用名词或明确动作，例如“科研大王 KYDW”“团队介绍”“项目与活动”“教学文档库”。
- 说明先回答“是什么”，再说明“包含什么”，最后给出“查看详情”或“进入项目”等动作。
- 不使用没有上下文的口号、对话式元话语和内部制作词汇。
- 不把专业解读放在非专业访客无法理解的快捷入口位置。
- 页面内部返回按钮使用“返回项目详情”“返回所属周次”“返回项目与活动”等明确层级名称。

## 8. 自审清单

每次改动后检查：

1. 第一次打开首页的访客能否在首屏知道 KYDW 是什么。
2. 顶部导航是否只有四项，并且每项职责互不重复。
3. 首页项目展示是否体现“当前重点 + 其他活动”，而非把某一项目误作团队主页。
4. 专业解读是否只在资源中心及其专题入口出现。
5. 周页面是否能同时理解体验项目和进阶项目的区别。
6. 项目详情页是否只保留教学项目、实践项目、参考答案及返回上级按钮；单层项目不显示进阶层级。
7. 教学文档是否同时出现在项目资料区与资源中心文档库。
8. 新增周次、项目、活动或专业专题时，是否只需添加数据和页面，不需要改变主页层级。
9. 桌面和移动端是否都能读清主次关系，右侧活动列是否保留局部滚动。
