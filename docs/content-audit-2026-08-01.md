# KYDW_TRY 内容与结构审查记录（更新至 2026-08-02）

## 审查目的

本次审查以真实访客第一次打开网站时的理解成本为标准，重点检查：

1. 首屏是否先说明 KYDW 是什么，而不是把某个项目当作团队主页。
2. 顶部导航、合集、项目、周次和教学文档之间是否层级清楚。
3. 文案是否像面向学生和家长的正式公开内容，不泄露制作过程，不加入无事实依据的标签和模板句。
4. 首页摘要、团队介绍、成员去向、项目页、资源中心和教学 HTML 修改后能否保持一致。
5. 新增体验材料后，只有确实有材料的方向才进入公开页面，未开放内容不以占位文字凑数。

## 审查依据

本次使用了两个独立审查视角：

- 内容审查：检查标题、摘要、项目说明、资源合集和专业解读是否重复、空泛或把内部工作语言暴露给读者。
- 结构与视觉审查：检查首页主次关系、负责人和成员高校布局、活动卡片、资源合集等在桌面端和窄屏中的信息密度。

两份意见中有一部分形成于新版体验材料导入之前，因此本记录只保留经过当前工作树、浏览器页面和导入结果复核后的结论。旧版 HTML 未作为内容、结构、样式、图片或交互参考。

## 本次发现与处理

### 1. 首页身份与团队概况

原先团队概况标题偏向“连接科研信息”等抽象口号，不能直接说明团队的作用。现改为“连接不同学校、专业与课题组”，正文保留团队来源、交叉方向、科研信息与学术资源、交流合作和成员推荐等核心信息。

负责人放在团队概况右侧的独立卡片中，卡片内部滚动；团队介绍与成员高校放在左侧，成果与负责人放在右侧。负责人顺序、成员高校分组和成果摘要均从 `content.js` 读取，不在首页另写一份数据。

### 2. 成员去向的一致性

已毕业成员高校按“直博”和“国内学硕/海外研究型硕士”横向分列，显示格式为“学校*人数”。北京大学医学部记录统一并入北京大学，因此首页、团队介绍页和成员去向页均显示北京大学直博 2 人。排序数组和去向记录必须同时检查，不能只改某一个页面上的文字。

团队页中信息量较低的“持续 / 项目与活动”统计改为“自主 / 运营方式”，避免把空泛的状态词当作团队事实。

### 3. 项目与活动层级

项目与活动总览不再写“位于首位”这类描述页面编排的句子，改为直接说明这里收录科研体验、科研培训、课程项目和专题交流。首页左侧仍突出本科生科研入门体验项目，右侧保留山东大学本科生暑期名校课程-神经影像学与人工智能、KYDW科研入门培训、复旦大学秋季学期本科生践悟课程和专题交流，但它们仍是并列的活动入口，不改变网站的团队身份。

体验项目的“项目环境准备”位于项目目录第一项，先完成网络访问、账户注册和 Kaggle 代码项目创建；它不计入科研方向项目数量。周入口根据项目开放状态决定：当前 Week 1 与 Week 2 可进入，Week 3—5 锁定。项目 00 只有体验版；项目 01—05 同时显示体验版和进阶版。每层仍按教学项目、实践项目和参考答案组织，进阶实践卡片同时提供设计报告模板，进阶答案卡片同时提供参考设计报告。没有教学材料的后续方向不会出现在公开项目目录。

### 4. 体验版与进阶版的内容关系

网站公开编号与来源材料编号的对应关系以 [`experience-materials.md`](experience-materials.md) 为唯一维护表。公开项目保持 00—05；现有站内文件名继续使用 `project-01`—`project-06`，避免已发布链接失效。项目 01—05 已替换为真实进阶材料，不再使用体验版临时副本。

体验版以完成和补全 Notebook 中的指定代码或文字为主，不要求提交报告。进阶版需要自行设计或选择方法，完成文献调研、验证设计、实验和结果解释，并提交设计报告说明方法选择。总览页、周页面和项目详情页均明确这一区别。

### 5. 教学 HTML

新版体验材料和进阶材料分别作为两个版本导入。教学页保留概念铺垫、数据说明、模型解释、交互模块、结果分析和实践入口。导入脚本只做必要的站点适配：

- 保持公开项目编号 00—05，并保留进阶教学 01—05 的原始版本标识；
- 增加返回项目详情按钮；
- 删除反复出现、不能帮助读者理解正文的 `.simulation-note` 模板说明。
- 生成设计报告模板、参考设计报告和进阶通用资料的网页阅读版，同时保留 Markdown 下载文件。

进阶教学 HTML 引用了 `进阶项目/assets/` 下的本地配图，但本次来源目录没有提供这些文件。导入时隐藏相关图框，避免破损图片；缺少路径已记录在 `content/advanced-manifest.md`，补齐后重新导入即可恢复。

没有把教学正文压缩成“输入、输出、准备要求、学习量”等空泛卡片，也没有把旧版废案带入新站。

## 公开页面禁用项

以下内容可以写在维护文档中，但不得出现在面向读者的页面中：

- 页面编排过程，如“位于首位”“当前网站工作性编排”“正式开放顺序”；
- 没有事实依据的“重点项目”“新增”“推荐”“合作方向”等状态标签；
- 人工智能对话、制作过程、旧稿审查和占位说明；
- 飞书链接、局域网地址和维护用地址；
- 为凑页面长度添加的“输入数据 / 任务输出 / 准备要求 / 学习量 / 开放状态”模板块；
- 对同一合集重复展开多份相同内容，或在项目页面复制资源中心的整段介绍。

## 下一次修改的起点

下一次新增项目时，先在 `content.js` 登记标题、摘要、周次和实际材料路径，再运行导入与页面检查；不要直接复制某个现有项目的公开文字。新增项目应自动进入对应周页、项目详情页和教学文档库，不应要求修改上层数量文案。补齐进阶教学配图或替换项目材料时，先更新 `experience-materials.md`，再检查项目详情页、资源中心教学文档库和对应返回路径。
