项目 01 参考设计报告：MRI 分割边界与不确定性

本报告对应参考 Notebook 的一种轻量实现。它说明一套可运行方案怎样形成，不代表唯一正确答案。实际结果以运行生成的 adv01_result.json 为准。

1. 研究问题与假设

研究对象是低级别胶质瘤 FLAIR 异常区域的二维分割。目标不是只提高平均 Dice，而是在患者级独立测试条件下同时观察区域重叠、边界偏差和输入扰动敏感性。核心假设是：轻量残差 U-Net 配合 BCE-Dice 可以形成稳定基线；水平翻转测试时增强的两次预测差异能够标出部分不稳定区域，但不能被解释为校准后的错误概率。

2. 数据与独立样本

推荐使用 Kaggle mateuszbuda/lgg-mri-segmentation。每个患者文件夹包含多张 FLAIR 切片和 _mask 掩膜。独立样本是患者，不是切片。相邻切片共享解剖和病灶，随机按切片划分会使测试结果过于乐观。参考代码因此先提取患者文件夹名，再使用 GroupShuffleSplit 形成训练、验证和测试患者集合，并用集合交集断言检查泄漏。

代码把图像缩放为 64×64 以缩短运行时间，掩膜使用最近邻插值。该处理会损失细边界，并且没有使用原始像素间距，所以 HD95 只能以像素单位报告。真实研究应读取 DICOM/NIfTI 的空间信息并进行三维或至少病例级连续评价。

3. 文献依据与候选方案

U-Net 的编码—解码与跳跃连接适合小样本生物医学分割。Tversky loss 可以改变假阳性和假阴性权重，适合小病灶和类别不平衡。贝叶斯深度学习与集成方法可估计不同来源的不确定性。候选路线包括基础 U-Net、残差 U-Net、Tversky、边界损失、MC dropout 和多模型集成。

参考答案选择残差 U-Net 与 BCE-Dice，原因是代码短、优化稳定、可在 CPU 或普通 Kaggle GPU 上运行，并且一次只引入一个结构变化。没有选择边界损失，是为了避免同时改变模型、损失和评价而难以归因。

4. 方法实现

残差块包含两层卷积和捷径映射。编码器逐级降低空间分辨率，瓶颈提取更大感受野，解码器通过双线性上采样和跳跃连接恢复定位。BCE 把每个像素视为二分类，Dice 项直接优化重叠。训练过程中保存验证 Dice 最优的状态，而不是默认使用最后一轮。

测试时对原图和水平翻转图分别预测，翻转结果恢复坐标后平均。两次概率的绝对差异作为 TTA disagreement。它只反映模型对水平翻转的敏感性；若病灶与图像方向强相关，翻转本身也可能产生不符合真实采集的扰动。

5. 评价设计

Dice 描述预测和真值的总体重叠。HD95 描述边界表面距离，能发现整体重叠尚可但局部边界偏移的问题。参考代码保存逐切片指标并再次按患者平均，避免切片多的患者支配结果。病例图同时展示 MRI、真值、预测和 TTA 差异。

可进一步加入 IoU、表面 Dice、体积误差、小病灶召回和人工修正时间。指标选择应对应使用场景：放疗边界更关心表面，疾病负荷研究更关心体积，筛查可能更关心漏检。

6. 结果解释

Quick Mode 只训练少量轮次，结果用于证明流程而不是比较方法。若真实数据结果较低，应先检查空掩膜比例、患者划分、图像/掩膜配对、归一化和模型是否只预测背景。若 Dice 尚可但 HD95 较差，可能存在边界小区域偏移；若 TTA 差异集中在边界，这与边界不稳定一致，但仍需与真实错误图叠加验证。

7. 局限

二维切片忽略层间连续性；缩放丢失细节；患者数量有限；标签可能存在人工差异；TTA disagreement 未校准；没有跨中心或不同 MRI 参数外部验证。演示回退数据只用于代码检查，不能形成医学结论。

8. 下一步实验

第一优先级是增加正式训练轮次并保存病例级最佳模型；第二是按病灶面积分层比较 BCE-Dice 与 Tversky；第三是加入体素间距后计算毫米 HD95；第四是在新中心或不同扫描协议数据上检查性能和不确定性。每一步只改变一个因素，便于解释。

9. AI/Agent 使用范例

可以让 Agent 检查文件配对、解释张量 shape、实现 Tversky 并写单元测试、定位背景塌缩或整理病例表。人工必须核对患者交集、掩膜插值、指标公式和论文链接。

10. 本包可运行性验证记录

本包制作时未挂载 Kaggle 的真实 LGG 数据，因此自动验证进入了明确标记的 demo 模式。演示数据上得到平均切片 Dice 0.962、平均患者 Dice 0.962，并成功生成病例预测、边界距离和 TTA 差异图。这些数值只证明数据读取、患者划分、训练、保存最佳权重和评价代码可以贯通；演示病灶由程序生成，任务远简单于真实 MRI，不能写入真实研究结论。挂载 Kaggle 数据后，报告应替换为真实患者数量、空掩膜比例、患者级结果分布、最差病例和失败原因。

11. 设计报告提交检查

完整报告至少应能回答：研究对象与目标区域是什么；独立样本为何是患者；数据和标签怎样形成；模型与损失为什么适合当前重点；哪些比较能够检验假设；指标与应用问题怎样对应；最差病例说明了什么；哪些结论受二维处理、缩放、标签差异和外部验证不足限制；下一步最值得做的单一实验是什么。代码没有完成时，也应保留数据审计、方案图、预期比较和失败定位。

12. 失败分析与替代方案

若模型几乎全部预测背景，首先检查正样本切片比例、掩膜是否因双线性插值而变成灰度、损失中前景权重是否过低，以及训练批次是否长期不含病灶。若训练 Dice 很高而患者级测试 Dice 很低，优先检查患者分组、扫描参数差异和模型容量，而不是继续增加训练轮次。若 Dice 与 HD95 给出矛盾结论，应打开病例图确认差异来自小的远距离假阳性、局部边界偏移还是病灶整体漏检。

替代方案应对应明确问题。小病灶漏检可比较 Tversky 或 focal Tversky；边界偏差可加入 surface loss 或距离变换监督；二维模型缺少层间信息可改为 2.5D 输入；不确定性需要更可信时可使用 MC dropout、深度集成或多标注者标签。报告中应说明替代方案准备解决什么，而不是罗列模型名称。

13. 复现产物与核对方式

参考 Notebook 应生成训练曲线、预测病例图、不确定性图和 JSON 指标。真实数据运行后还应保存患者划分清单、模型参数、随机种子、软件版本和逐病例表。复现检查不只看代码能否再次运行，还要确认再次运行使用了同一患者划分、同一标签定义和同一评价单位。
